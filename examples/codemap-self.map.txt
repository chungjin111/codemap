# 코드맵 (codemap)
코드베이스를 **이름 → 뼈대 → 핵심 줄** 순으로 좁혀 읽고, 클릭형 마인드맵 HTML 한 장으로 만드는 도구.

## 명령 받기 @skill_scripts/codemap.py
scan · skeleton · read · build 네 단계를 하위 명령으로 나눠 받는다.
~ 하위 명령 등록 @66-72
`argparse` 의 서브파서로 단계마다 명령을 하나씩 만든다. 각 단계가 파일(manifest.json → skeleton.md → analysis.json)로 결과를 넘기므로, 중간에 끊겨도 그 단계부터 다시 실행할 수 있다.
68: `required=True` — 하위 명령 없이 실행하면 사용법을 보여 준다.
70-72: 첫 단계 `scan` 은 폴더와 zip 을 모두 받는다.

## 이름만 보고 거르기 @skill_scripts/scan.py
파일을 열지 않고 경로와 크기만으로 분석 대상을 고른다. 여기서 버린 것은 토큰을 0 쓴다.
-> 뼈대 뽑기 : manifest.json

### 폴더째 버리기
node_modules, dist, .git 같은 폴더는 안으로 내려가지도 않는다.
~ 폴더 이름 판정 @dir_drop_reason
폴더 **이름 하나만** 보고 버릴지 정한다. 버릴 때는 사유 문자열을, 남길 때는 `None` 을 돌려준다. 사유는 나중에 HTML의 '분석 범위' 패널에 그대로 표시된다.
138-140: `DIR_RULES` 표에서 찾는다: 의존성 / 빌드 산출물 / 버전관리 / 자동 생성 / 문서.
144-147: 테스트·예제 폴더는 옵션(`--keep-tests`, `--keep-samples`)으로 되살릴 수 있다.
~ 내려가지 않고 건너뛰기 @218-232
`os.walk` 는 `dirs` 목록을 제자리에서 고치면 그 폴더로 내려가지 않는다. 이 성질을 이용해 버릴 폴더를 **훑는 비용조차 없이** 건너뛴다.
227-228: 이름이 `env` 처럼 애매해도 `pyvenv.cfg` 가 있으면 가상환경으로 본다 (존재 여부만 확인, 내용은 읽지 않음).
229: 사용자가 `--include` 로 지정한 폴더는 규칙보다 우선한다.

### 파일 하나씩 판정
잠금 파일 · 바이너리 · 생성 코드 · 테스트 · 문서 · 스타일 · 데이터 순으로 걸러 낸다.
~ classify_file() @classify_file
규칙을 **위에서부터 차례로** 적용해 처음 걸리는 사유로 버린다. 끝까지 살아남고 코드 확장자인 파일만 `keep` 이 된다.

`package.json` 같은 명세 파일과 최상위 README 는 코드가 아니어도 남긴다. 몇 줄만 봐도 프로젝트 성격을 알려 주는 값싼 단서이기 때문이다.
160-163: 명세 파일·README 는 예외적으로 유지.
168-171: `*.min.js`, `*_pb2.py`, `*.g.dart` 등 이름 패턴으로 생성 코드를 알아본다.
176-181: 코드라도 1MB 를 넘으면 생성물·데이터로 보고 제외한다.

### 반복 묶음 접기
같은 폴더에 같은 이름 패턴이 여러 개면 대표만 남긴다.
~ 번호 시리즈 찾기 @296-304
`0001_init.sql`, `page03.ts` 처럼 번호가 붙은 파일이 한 폴더에 4개 이상이면 '번호 시리즈' 묶음으로 본다. 이런 파일은 구조가 거의 같아서 하나만 읽어도 충분하다.
299-300: 앞에 번호가 붙거나(`v2_`, `0001_`) 끝이 두 자리 이상 숫자면 해당.
303: `always: True` — 프로젝트 크기와 상관없이 항상 접는다.
~ 접을지 결정 @381-394
묶음을 찾았다고 무조건 버리지는 않는다. `*Controller` 같은 접미사 묶음은 각자 다른 기능일 수 있으므로 **큰 프로젝트일 때만** 접는다. 접으면 대표 파일만 남고 나머지는 이름만 기록된다.
384: 판단 기준: 번호 시리즈이거나, 프로젝트가 크거나(`big`), 사용자가 강제했거나.
385: 대표는 가장 큰 파일과 중간 크기 파일 — 가장 풍부한 것과 평균적인 것.
390-392: 나머지는 목록에서 빼고 '반복 패턴' 사유로 기록.

### zip 은 살아남은 것만 풀기
걸러진 파일은 압축 해제조차 하지 않는다.
~ 선별 압축 해제 @402-418
zip 입력이면 이름 목록에 규칙을 먼저 적용하고, **통과한 파일만** 작업 폴더에 푼다.
410-412: 압축 폭탄 방지: 합계 300MB 를 넘으면 중단.
414-415: 경로가 작업 폴더 밖을 가리키면 건너뛴다 (zip-slip 방지).

## 뼈대 뽑기 @skill_scripts/skeleton.py
원문 대신 시그니처 · 호출 관계 · import 그래프만 추린 요약본을 만든다. 로컬에서 돌므로 토큰 0.
-> 필요한 줄만 읽기 : skeleton.json

### 함수·클래스 찾기
언어에 따라 두 가지 방법을 쓴다.

#### 파이썬: 문법 트리
`ast` 로 정확한 줄 범위와 독스트링 첫 줄을 얻는다.
~ py_symbols() @148-166
파이썬은 표준 라이브러리 `ast` 로 파싱한다. 정규식보다 정확하고, 데코레이터(`@app.route` 등)가 붙은 줄부터 시작 줄로 잡아 준다.
152-154: 데코레이터가 있으면 그 줄을 시작으로 삼는다.
156-161: 독스트링은 첫 줄만 70자까지 — 설명은 값싸고 신호가 좋다.

#### 그 외 언어: 정규식
JS/TS, Go, Rust, Java, Kotlin, Swift, Dart 등 계열별 패턴.
~ generic_symbols() @269-299
한 줄씩 보며 언어 계열별 정규식에 맞는 '정의 줄'을 찾고, 중괄호 짝(`brace_end`)이나 들여쓰기(`indent_end`)로 끝 줄을 구한다.
283-286: `if (...) {` 나 `return foo(x)` 를 함수 정의로 오인하지 않도록 제어 키워드를 걸러 낸다.
287-294: 끝 줄 찾는 방식을 언어 계열에 따라 고른다.

### 호출 관계 잇기
함수 본문에서 '프로젝트 안에 정의된 이름'을 부르는 곳만 골라낸다.
~ 이름표 만들고 본문 훑기 @484-503
먼저 프로젝트 전체의 함수·클래스 이름표(`defined`)를 만든다. 그다음 각 함수 본문에서 `이름(` 꼴을 찾아, 이름표에 있는 것만 호출로 기록한다. 이것이 마인드맵의 **흐름**을 잡는 재료다.
485-489: 이름 → 그 이름이 정의된 파일들.
498: `get`, `run` 처럼 너무 흔한 이름은 정보가 없어 뺀다.
501: 같은 이름이 4개 이상 파일에 있으면 모호하므로 제외 (같은 파일 안이면 인정).

### 중요도 매기기
진입점 · 많이 import 되는 파일이 위로 온다.
~ 점수 계산 @517-538
파일마다 점수를 매겨 정렬한다. 이 순서가 '예산이 모자랄 때 무엇을 먼저 자세히 보여 줄지'를 결정한다.
521: 기본 점수: 이 파일을 import 하는 파일 수(가중 4) + 내보내는 import + 길이.
522-525: `__main__`, `app.listen(` 같은 진입점 표시나 `main`/`app`/`index` 이름에 가산점.
526-532: util·config 류, 깊은 경로, 내용이 중복된 파일은 감점.

### 예산 안에서 상세도 조절
중요한 파일은 자세히, 덜 중요한 파일은 한 줄, 나머지는 이름만.
~ 3단계 상세도 @618-641
중요도 순으로 돌면서 토큰 예산(기본 12,000)을 채운다. 예산의 80%까지는 **상세**(시그니처+호출), 100%까지는 **요약**(한 줄), 넘으면 **이름만** 싣는다. 프로젝트가 아무리 커도 뼈대 크기는 예산을 넘지 않는다.
619-622: 내용이 완전히 같은 파일은 이름만.
623-627: 함수 구성이 똑같은 파일(CRUD 류)은 첫 파일만 자세히, 나머지는 '같은 구조' 표시.
628-634: 예산 80% 전까지는 상세 블록.

## HTML 로 조립 @skill_scripts/build.py

### 참조 → 실제 코드
LLM 은 코드를 다시 쓰지 않는다. 줄 번호만 주면 여기서 꺼낸다.
~ 검증하고 꺼내기 @80-91
출력 토큰은 입력보다 훨씬 비싸다. 그래서 analysis.json 에는 `file` 과 `lines` 만 있고, 코드 원문은 이 스크립트가 디스크에서 읽어 넣는다. 범위가 틀리면 오류로 알려 줘서 LLM 이 고칠 수 있게 한다.
80-82: 줄 범위가 파일을 벗어나면 오류.
84-86: 조각 하나는 최대 80줄 — 길면 핵심만 다시 고르게 한다.
91: 공통 들여쓰기를 걷어 내 박스 안에서 왼쪽 정렬되게 한다.

### 템플릿에 끼워 넣기

~ 데이터 주입 @184-190

189: 코드 안에 `</script>` 가 있어도 깨지지 않도록 `<` 를 유니코드 이스케이프로 바꾼다.

## 마인드맵 화면 @template/mindmap.html
박스를 누르면 하위 기능과 코드가, 코드를 누르면 설명이 펼쳐진다. 다시 누르면 접힌다.

### 펼치고 접기

~ setOpen() @421-436

423-428: 처음 펼칠 때 하위 박스를 만든다.
433-434: 손잡이 표시: 닫혀 있으면 하위 개수, 열려 있으면 −.
